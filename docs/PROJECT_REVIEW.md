# 项目接手评估 · 2026-09-29

## 结论

可作为团队继续开发的浏览器游戏基线，当前五关功能回归通过。工程仍带有单文件原型拆解的痕迹，建议渐进整理后扩关。

## 已核实

- 项目为原生 JavaScript + 内嵌 Three.js r180，无服务器后端、无 npm 依赖安装流程。
- `tools/build.py` 按固定顺序拼接模块，生成约 2.1 MB 的 `app.js` 和约 91 MB 的完整 HTML。
- 交付含 12 份资源，约 65 MB；最大 GLB 为 51,732,532 字节，二进制素材已纳入 Git LFS。
- 本机 Chromium 浏览器：第一关 21/21、第二关 18/18、第三关 18/18、第四关 23/23、第五关 32/32，合计 112/112，浏览器错误列表为空；第三、第五关截图检查画面正常。
- 构建、资源哈希和单文件内嵌资源校验、打包 JS 与单文件 JS 语法检查通过。
- 未进行实体手机性能验收、完整真人通关评价、file 协议运行验证；未核验交付文档所称线上站点。

## 本次修复与建仓准备

1. 原验证脚本强制读取交付者电脑的绝对路径，克隆后必然失败。现改为基于仓库资源清单校验；原始 HTML 比对仅在显式传入 `--source` 时执行，未执行时报告 SKIP。
2. 一次性导入脚本原先无保护地覆盖源码。现必须提供源文件路径及 `--force`，避免误当构建命令。
3. 补充 UTF-8 文件读写，移除当前清单中的个人电脑绝对路径，补充环境文件与产物忽略规则。
4. 建立交付基线标签、LFS、当前 README、协作指南、PR 模板和 GitHub Actions 构建校验。
5. 保留现有游戏行为与已跟踪生成文件，原交付文档移至历史目录。

## 后续优先级

- 优先将浏览器 112 项回归纳入 CI，目前 CI 只覆盖构建、完整性、语法和生成文件同步。
- 从 `engine.js` 逐步拆出第三方库、前三关和测试；它目前约 2 MB，共享变量多，多人同时修改易冲突。
- 第六关已有独立代码，但构建列表及主流程均未接入，不能作为可玩第六关交付。
- 首屏顺序加载多个模型，最大单模型约 49.3 MiB，测试记录第一关约 189 万渲染三角形；弱网与移动端应实际测量，再决定压缩、简模和按关加载。
- 补齐模型/贴图来源及许可记录，核对内嵌第三方库声明；当前交付没有独立素材授权台账，也未提供项目统一许可证。
